1. **Model-driven structured output** through the Model Gateway: a JSON schema, validation, and one repair retry. Fields:
   - role, must-haves, nice-to-haves, experience range, location/work mode, compensation, notice period, disqualifiers;
   - **contradictions and missing information**;
   - **client clarification questions**, **screening questions**, and **Boolean search strings**.

   Every item cites the phrase in the JD it came from. Missing means `unknown`, never guessed.
2. **Guardrail validator:** reject or strip any criterion based on a protected attribute (gender, age, religion, caste, marital status, disability, photo, name). This is tested.
3. **Persist and approve:**
   - `agency_scorecards`: owner, status `draft | approved`, version, and the source JD hash (not a copy of client data beyond what's needed).
   - Endpoints to create a draft, edit it, and approve it; the owner only; audited.
   - Only an **approved** scorecard can be used later.
4. **Minimal UI** in the JennySol app: paste JD → draft → edit fields → Approve. Mobile-friendly. It's a new screen, so it can ship.
5. **Eval:** at least 10 public or synthetic JDs (none from a real client). Measure field accuracy, contradiction detection, protected-attribute leakage (must be 0), and latency. Write the results into `docs/JENNYSOL-EVAL-RESULTS.md`.
