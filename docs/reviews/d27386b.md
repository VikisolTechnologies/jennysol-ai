## Response, 26 Sep 2026 (evening) — ADR-007 §12 steps 2–6

Built the four pieces ADR-007 §12 requires before the Agency scorecard is allowed to touch the
cloud at all, plus the scorecard's own rebuild onto that path:

- **Step 2 — CONTROLLED_CLOUD tier + always-on enforcement.** `privacyTier.ts` gained the tier
  and a `forceEnforce` parameter threaded through `applyPrivacyTier` → `routeChatCompletion` →
  `streamChatCompletion`. It's additive, never a replacement for the existing global
  `PRIVACY_TIER_ENFORCE` watch-only flag — an agency call passes `forceEnforce: true` and is
  enforced regardless of that flag's state. Tests 9(a) (forced tier holds even with the global
  flag off, both for `PRIVATE` and `CONTROLLED_CLOUD`) and 9(b) (a provider failure never
  escalates to an unpermitted one — throws `AllProvidersUnavailableError` instead) are in
  `privacyTier.test.ts` and `modelRouter.test.ts`.
- **Step 3 — agency tenant model + kill switches.** `services/agency/tenant.ts`: a tenant belongs
  to an agency, not a user; `requireMembership()` is the real isolation boundary (throws for a
  non-member or an unknown tenant, indistinguishably — never reveals which). Two kill switches
  (`AgencyTenant.cloudProcessingDisabled` per-agency, `AGENCY_CLOUD_DISABLED` global env var)
  each independently collapse `CONTROLLED_CLOUD` down to `PRIVATE_ONLY`. Cloud processing needs an
  explicit opt-in (`dataProcessingSetting`) — the default is locked to `private_only`.
- **Step 4 — JD redaction that fails closed.** `services/agency/redaction.ts` strips company name,
  email, phone, URL deterministically (regex, never model-based), then re-verifies the *output*
  with separately-broader patterns before allowing the draft to proceed — not the same pattern
  checking itself twice. A bare domain the redaction pass doesn't catch (no `http(s)://`/`www.`
  prefix) is the real test case proving this: it survives in `result.redacted`, but `result.ok` is
  `false`, and `draftAgencyScorecard()` refuses before ever calling a model.
- **Step 5 — content-free audit records.** `services/agency/modelCallAudit.ts`'s
  `agency_model_call_audit` table has no column that could ever hold prompt or content text — test
  9(f) asserts this by literally introspecting `PRAGMA table_info` and checking none of
  `prompt/content/text/message/jd/jd_source/requirement` appear. It records tier requested/resolved,
  redaction-ok, provider, and latency only, on both success and refusal.
- **Scorecard rebuild.** `services/agency/scorecard.ts`'s flow is now: redact → resolve tier (real
  tenant state, both kill switches) → refuse *before any model call* if the resolved tier isn't
  `CONTROLLED_CLOUD` → call the model with `forceEnforce: true` → guardrail (protected-attribute
  removals now set `escalate: true` and a generic, non-hardcoded `refusalNotice`, and preserve the
  original JD quote in the audit trail rather than discarding it) → tenant-scoped persistence via
  `scorecardStore.ts`, whose `approve()` now refuses a flagged scorecard (`ScorecardRequiresReviewError`)
  until the actor explicitly passes `reviewed: true`. The old `jennysol.draftAgencyScorecard` chat
  tool — which bypassed this entire pipeline — was removed outright, not deprecated.
